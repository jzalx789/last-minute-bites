# 隱私與用戶協議交接

版本 1.4，2026-11-10（香港時間）。本頁供維護者檢查，不是法律意見或合規認證。

## 已落實的行為

- 公開雙語用戶協議／隱私政策，內容以 `web/legal.js` 為準，版本 `2026-11-10.1`。主動同意及時間在 `user_consents` 保存；不替舊帳戶補造同意紀錄。
- 營運者目前按專案團隊標示；公開私隱聯絡電郵由維護者提供：`Bite.limited@gmail.com`。電郵名稱不代表已註冊有限公司。
- 文字 AI／照片 AI 分開、預設關閉；送出前及回覆後均檢查授權，撤回或清除歷史會使舊請求失效。必要 cookie／裝置選材／介面快取及權限用途已披露，沒有加入行銷或廣告追蹤。
- 匯出不包含帳密雜湊、session token、推播私鑰或其他成員帳戶。刪帳須密碼、電郵及明確確認，先處理共享廚房擁有權；交易失敗整批回滾。他人庫存、先前確認的消耗及已下載副本不會被任意撤銷。
- 使用者資料保留、個人 AI 歷史清理、約 30 天配額紀錄及不含帳戶識別的合計次數均按實作說明。App 內刪除不等於供應商備份／日誌即時物理刪除。
- 食譜、影像辨識、日期和通知限制清楚披露；沒有宣稱可判斷實際食用安全、過敏原完整性、醫療／營養結果或保證送達。責任條款保留依法不能排除的責任及強制權利。

## 正式商用前仍須確認

1. **營運者法定身份與聯絡渠道**：由誰承擔資料使用者／營運者職責、適用地區、有效地址，以及該電郵是否持續有人處理查閱、更正、刪除與投訴。不要把原型協議當成公司註冊或法律審查。
2. **供應商合約**：確認目前實際使用的 API／託管合約、處理地點、保留時間、訓練／改進用途、退出機制及資料處理安排。一般消費者網站政策與特定 API 合約未必相同；沒有證據時不能聲稱零保留、永不訓練或限定香港境內。
3. **跨境與敏感資料**：依實際使用者所在地判斷必要告知／同意、兒童規則及跨境安排。食材限制盡量用食材名稱，不要求醫療診斷、身份文件或其他敏感內容。
4. **營運程序**：制定查詢回覆、身份核實、事件應變、備份／日誌清理和服務結束安排，並確認現有供應商能力；不要承諾未配置的時限、通知或刪除保證。
5. **法律審閱**：讓了解適用地法律的專業人士審閱協議及私隱政策，特別是營運者身份、消費者權利、責任限制與資料保護要求。文字與自動測試不能保證免除法律責任。
6. **電郵能力**：目前沒有 SMTP／交易郵件服務，因此沒有電郵擁有權驗證或自動密碼重設信。加入時須實作真正的一次性／到期 token、限流及交付驗證，不能只顯示成功訊息。
