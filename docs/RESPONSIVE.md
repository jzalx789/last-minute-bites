# 可調整視窗與摺疊屏適配

版本 1.4.3；2026-11-16（香港時間）。

## 指引如何套用至目前產品

參考 [Apple iPhone Duo 準備工作](https://developer.apple.com/cn/iphone-duo/prepare/)。指引要求依目前視窗可用空間配置、在會話中持續回應尺寸變化，避免按裝置型號、固定尺寸或裝置方向決定版面。

Last Minute Bites 是 Safari／瀏覽器 Web App。原生 UIKit／SwiftUI、Xcode SDK 版本及 App Store 截圖／徽章的步驟不適用於此程式碼；沒有因此建立原生 APK／IPA、安裝 SDK 或宣稱獲 Apple 認證。Apple 指引亦沒有要求所有摺疊裝置使用同一組固定像素或自行假設鉸鏈寬度。

## 此次實作

- `static/index.html` 啟用 `viewport-fit=cover`；`static/style.css` 統一讀取系統回報的四邊 safe-area inset，主畫面及底部操作避開左右、上下系統區域。不硬編碼某款手機的缺口或狀態列尺寸。
- `static/app.js` 在 visual viewport 的 resize／scroll、視窗 resize、pageshow 及焦點事件重新讀取可用範圍。除了高度及頂部位移，亦處理寬度及水平位移；不採用螢幕型號或固定方向判斷。
- 確認、協議、掃描和消耗彈窗，以及狀態提示，依同一可用範圍及安全區設定尺寸和位置。消耗清單保留獨立捲動及可到達的確認／取消按鈕。
- 尺寸調整只更新版面參數，不重建表單或觸發存檔／食譜生成。原有原生登入頁捲動、已登入頁內捲動及底部導覽保留。
- 縮放時交回瀏覽器原生放大／平移，沒有停用 pinch zoom。原有 CSS 依可用視窗尺寸切換欄位和格線，沒有以 iPhone／iPad 型號選擇版面。
- 更新前後端版本為 1.4.3，並更新公開 shell 快取版本；帳戶、庫存、服務綁定和資料庫沒有遷移。

## 自動化驗證

新增 `tests/responsive_browser.py`，在隔離的本機 Worker 與測試 AI 服務上分別使用 Chromium／WebKit：

1. 同一個表單在窄、寬、短及分屏形狀之間切換，驗證名稱、數量、備註、焦點和游標不變，且尺寸切換沒有新增 POST 寫入。
2. 注入左右不對稱的安全區，驗證內容不越界、不橫向溢出。
3. 模擬可視範圍變窄並水平／垂直位移，驗證 App 跟隨目前範圍。
4. 在調整尺寸後檢查確認／消耗彈窗四邊與取消操作，確保庫存保留。
5. 檢查縮放退回原生版面，以及登出後登入頁仍使用原生文件捲動。

執行方式及服務啟動指令見 README。CI 對兩個引擎均執行此項測試；原有 keyboard、iPhone、大小字體及多廚房測試仍保留。

## 尚未驗證的裝置行為

上述是瀏覽器尺寸與事件測試，注入安全區亦非真實裝置感應器資料。不能將它描述為 iPhone Duo 實機、Xcode Duo／可調整大小 OS 模擬器或 macOS iPhone 鏡像測試。

仍須在真機／OS 模擬器驗證內外屏切換、實際 Safari 與主畫面模式、系統側邊區域、軟鍵盤、橫直向及分屏。沒有新增雙屏鉸鏈或半摺姿態專用介面；未有系統回報時不虛構摺痕遮擋位置。瀏覽器可用功能和視窗事件亦不能取代 OS 裝置驗收。
